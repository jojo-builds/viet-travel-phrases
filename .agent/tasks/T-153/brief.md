# T-153 feature brief

## Source
- Follow-on after completed `T-141`
- Orchestrator-approved overnight packet on `2026-04-23`

## Feature
Bootstrap the first Tagalog additive answer-page sidecar and enrich a substantial first set of listing-page hubs so Tagalog starts using the same AI-shaped answer-page system that Viet is proving.

## Intent
- stop leaving Tagalog as only a relation-ready pack without a true listing-page answer seam
- create the first real Tagalog answer hubs so the future native app is not forced to invent Tagalog page content later
- keep Tagalog moving in parallel with Viet, but in a way that strengthens the exact product area the user cares about: listing-page usefulness, phrase links, and module logic
- prove the answer-page system is a reusable family content model, not a Viet-only special case

## Locked product principle
- Listing pages are AI-shaped answer pages, not simple phrase detail pages.
- The family model should be reusable across languages, while still allowing language-specific phrasing and culture-aware notes.
- Phrase text stays in the phrase-source CSV; answer-page structure and module payloads stay additive.

## Required behavior from the source direction
- do not stop at relation-only cleanup
- create a real Tagalog answer-page sidecar
- land meaningful Tagalog listing-page content, not a tiny demo
- use the existing Tagalog relation and phrase-source work as the base rather than reinventing a disconnected system

## Product constraints from orchestrator
- this belongs on the Tagalog content branch/worktree, not the Viet or UI branch
- this should be a large overnight content/database task, not prep-only work
- the task must justify the full review-gate overhead with visible product value
- this is a meaningful task and must use the full 3-gate / 4-reviewer contract
