# Gate 1 Pass 1: Recovery Policy Review
## Summary
This direction is safe and well-scoped if the new behavior stays in a bounded recovery-handoff path under queue maintenance, not as a silent expansion of cheap repair or desktop restart. It matches the concrete gap shown by T-139 and T-140: meaningful work was preserved, but closeout still required manual recovery-task authoring.

## Key Risks
- Do not let routine repair or desktop restart start creating tasks implicitly. Current repair is narrowly defined as reclaim normalization plus queue-index rebuild ([QUEUE_REPAIR.md](</E:/AI/SpeakLocal-App-Family/.agent/QUEUE_REPAIR.md:19>), [queue_tool.py](</E:/AI/SpeakLocal-App-Family/.agent/queue_tool.py:1277>)); current desktop recovery is app/ledger-only ([QUEUE_MAINTENANCE.md](</E:/AI/SpeakLocal-App-Family/.agent/QUEUE_MAINTENANCE.md:67>), [queue_tool.py](</E:/AI/SpeakLocal-App-Family/.agent/queue_tool.py:1312>)). Keep handoff generation as an explicit maintenance-capable path with a non-destructive dry-run/inspection mode.
- Duplicate avoidance has to live in durable lifecycle truth, not only in `queue-index.json` or the desktop recovery ledger. The repo contract says `state.json` is lifecycle truth and the index is advisory only ([AUTOMATION.md](</E:/AI/SpeakLocal-App-Family/.agent/AUTOMATION.md:27>), [README.md](</E:/AI/SpeakLocal-App-Family/.agent/README.md:21>)). The implementation should preserve an explicit original-task to recovery-task link that survives index rewrites and interrupted runs.
- The generator must preserve both historical truth and the meaningful-task contract. T-139/T-140 show the right historical posture as `blocked` plus `interrupted-awaiting-recovery` while keeping the original meaningful review requirements intact ([T-139 state](</E:/AI/SpeakLocal-App-Family/.agent/tasks/T-139/state.json:4>), [T-140 state](</E:/AI/SpeakLocal-App-Family/.agent/tasks/T-140/state.json:4>)). The new recovery task must carry the relevant lock/scope and be explicit about whether it is closeout-only or allowed to repair worktree truth ([AUTOMATION.md](</E:/AI/SpeakLocal-App-Family/.agent/AUTOMATION.md:40>)).
- “Landed work worth salvaging” needs a strict durable test. Ordinary stale ownership is already handled by reclaim classification/normalization ([queue_tool.py](</E:/AI/SpeakLocal-App-Family/.agent/queue_tool.py:662>), [queue_tool.py](</E:/AI/SpeakLocal-App-Family/.agent/queue_tool.py:999>)); without a stronger salvage threshold, the tool could over-generate recovery tasks for work that should just remain reclaimable.

## Recommendation
Approve Gate 1. Implement this as a bounded maintenance/recovery-handoff command with `--dry-run` or equivalent inspection output, durable bidirectional linkage, explicit salvage eligibility, and ordering that only flips the original task into interrupted historical truth after the new handoff packet exists. Preserve current `repair` and `desktop-recover` semantics, keep `state.json` authoritative, and require generated recovery tasks to retain the same review and scope truth needed for safe closeout.

Approval: APPROVE
