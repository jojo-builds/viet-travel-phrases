## Outcome

T-163 moved the SQLite plan from architecture into a generated offline fixture. The current app runtime still uses JSON, but the repo now has a deterministic build-time path for compiling Vietnam phrase/content/audio/search data into a SQLite read model.

## What We Learned

The generated fixture confirms the current phrase universe can be represented as a canonical phrase graph:

| SQLite surface | Count |
| --- | ---: |
| Scenarios | 18 |
| Phrase clusters / source families | 900 |
| Phrases | 919 |
| Canonical phrase pages | 919 |
| Page aliases | 920 |
| Page sections | 1,304 |
| Page section items | 2,083 |
| Breakdown tokens | 720 |
| Search documents / FTS rows | 919 |
| Audio assets | 3,756 |
| Audio usages | 3,165 |
| Audio text dedupe rows | 2,343 |
| Missing audio audit rows | 0 |

This supports Jojo's direction: every phrase can have exactly one canonical page, with aliases and relations preventing duplicate pages.

## Decisions Locked In

- SQLite remains a generated offline read model, not the authoring source.
- `phrase` is the atomic learner-facing unit.
- Legacy family IDs become clusters/aliases, not competing page identity.
- Authored pages and section `detailPageID` links can resolve through canonical phrase pages or aliases.
- Search can be represented with `search_document` and FTS5.
- Audio now has a clearer split between `audio_asset`, `audio_usage`, and text dedupe.

## Important Constraint

The generated SQLite file is not yet bundled into the native app. `native-ios/project.yml` still excludes `LanguagePacks`, so Swift cannot reliably open `Resources/LanguagePacks/viet/speaklocal-viet.sqlite` from `Bundle.main` yet.

## Product Meaning

This removes a lot of the mystery around "why are there 900 families, 919 phrases, and 2,427 MP3s?" The app data now has a path toward one clean offline graph:

- Home can eventually pull categories, relationship clusters, recent phrase pages, and practice decks from the same database.
- Search can rank canonical pages while avoiding duplicate `Chào anh`-style pages.
- Audio can be audited by usage instead of guessing from filenames.
- Practice can be generated from the same phrase/page/relationship graph instead of becoming a separate content system.
